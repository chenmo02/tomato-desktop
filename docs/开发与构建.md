# 开发、测试与发行

以下命令从仓库根目录运行，使用 PowerShell 7。需要 Windows 和 .NET 10 SDK。

## 编译与运行

```powershell
dotnet build native/DesktopNook.App -c Release
dotnet run --project native/DesktopNook.App -c Release
```

正常运行会操作真实桌面及当前用户数据。开发调试建议先使用隔离模式：

```powershell
$profile = Join-Path $env:TEMP ('DesktopNook-dev-' + [guid]::NewGuid().ToString('N'))
dotnet run --project native/DesktopNook.App -c Release -- --sandbox $profile
```

隔离桌面为 `<profile>/Desktop`，数据为 `<profile>/Data`，回收站及偏好使用测试状态。不要把日常桌面或工作文件夹作为隔离根目录。

## 构建单文件程序

```powershell
pwsh -NoProfile -File native/scripts/Build.ps1
```

脚本重新生成多尺寸 ICO、执行核心检查，并生成含运行时的 Windows x64 单文件程序，输出到 `native/artifacts/win-x64/DesktopNook.exe`。该 EXE 只作为安装包的载荷，不单独发布。已完成核心检查且只需重复打包时可加 `-SkipTests`。

## 测试

核心测试不依赖第三方测试框架：

```powershell
dotnet run --project native/DesktopNook.Tests -c Release -- native/test-results/core.json
```

后台资源自检不启动主窗口、不读取或改动真实桌面，不需要隔离目录，也不操控鼠标。它验证图标缓存按预算淘汰、解码线程空闲后自动退出、挂起态缓存可释放，以及自动收纳在面板可见 / 收起时的 15 秒与 60 秒间隔：

```powershell
$report = Join-Path $env:TEMP ('DesktopNook-resource-' + [guid]::NewGuid().ToString('N'))
$exe = (Resolve-Path native/artifacts/win-x64/DesktopNook.exe).Path
& $exe --resource-self-test $report
Get-Content (Join-Path $report 'resource.json')
```

成功写出 `resource.json`（含全部断言与前后缓存 / 线程快照），失败写出 `failure.txt` 并返回非零退出码。开发阶段也可直接对 `dotnet build` 产出的 `DesktopNook.exe` 使用该参数。

按钮前景色自检也是纯资源探测：`--verify-button-contrast <报告目录>` 遍历原生/玻璃 × 浅色/深色四套色板，验证次要按钮与设置页下拉选择器的文字始终等于当前 `WinText`、深色态亮度足够，并输出 `button-contrast.json` 与深色按钮渲染图 `dark-secondary-buttons.png`；成功时报告 `failed` 为空、退出码为 0。

原生测试必须运行在可交互的 Windows 桌面，且使用新建专用目录。部分检查短暂操控鼠标，期间请暂停其他鼠标操作。

```powershell
$exe = (Resolve-Path native/artifacts/win-x64/DesktopNook.exe).Path
$profile = Join-Path $env:TEMP ('DesktopNook-ui-' + [guid]::NewGuid().ToString('N'))
$test = Start-Process -FilePath $exe -ArgumentList @('--sandbox', ('"' + $profile + '"'), '--ui-self-test') -PassThru
$test.WaitForExit()
Get-Content (Join-Path $profile 'native-verification.json')
```

将 `--ui-self-test` 替换为 `--size-self-test` 可检查预设尺寸、固定图标大小、真实鼠标缩放、偏好保存及版本文字。尺寸检查报告为 `sizing-verification.json`，截图也在该隔离目录中。

`--dpi-self-test` 检查混合 DPI 多屏下的窗口行为：向窗口补发 `WM_DPICHANGED`，模拟「DIP 尺寸不变、物理矩形放大 1.5 倍」的换屏场景，验证圆角 `HRGN` 随窗口重裁、内容层与裁剪覆盖整窗、壁纸对齐改用虚拟屏幕物理坐标。报告为 `dpi-verification.json`。该自检不改动真实显示器设置，但会临时改变自检窗口尺寸，运行期间请勿操作鼠标。

`--backdrop-self-test` 检查**未经任何人为干预的冷启动状态**：固定以玻璃皮肤启动，在窗口首帧后读取 DWM 背板类型、WPF 清屏色、实际生效的窗口底色画刷、自绘背景层透明度与壁纸裁切区域，并抓一张真实屏幕图（`backdrop-cold-start.png` / `backdrop-cold-start-crop.png`，`RenderTargetBitmap` 看不到 DWM 背板）。它用于拦截「启动不透明、进设置切一次 UI 才透明」这类初始化时序回退。报告为 `backdrop-verification.json`。系统会临时以隔离注册表键写入玻璃皮肤偏好，不影响日常设置。

在线更新专项验证（`Repository` 留空时会写出 `skipped=true` 的报告并直接返回成功；现已配置发布仓库，验证会实际执行）：

```powershell
$report = Join-Path $env:TEMP ('DesktopNook-update-' + [guid]::NewGuid().ToString('N'))
$test = Start-Process -FilePath $exe -ArgumentList @('--verify-online-update', ('"' + $report + '"'), ('"' + $exe + '"')) -PassThru
$test.WaitForExit()
Get-Content (Join-Path $report 'online-update-verification.json')
```

加 `--live` 时会访问当前仓库的真实最新正式版并下载；应在本地程序与该发行版对应时使用。

`--live-verify`、`--collection-inventory` 等维护入口会读取真实本机数据；部分入口可改变真实桌面状态，`--collection-inventory ... --apply` 会执行恢复操作。它们不属于常规测试命令，不应在日常数据上随意运行。

## 构建安装包

先安装 Unicode NSIS，将 `makensis` 加入 PATH。**日常打包在仓库根目录依次执行两条命令即可**（PowerShell 7）：

```powershell
pwsh -NoProfile -File native/scripts/Build.ps1
makensis /V2 native/scripts/Installer.nsi
```

第一条生成 `native/artifacts/win-x64/DesktopNook.exe`（含运行时的单文件程序，仅作安装包载荷，不单独发布；同时刷新多尺寸 ICO 并跑核心检查，已跑过检查可加 `-SkipTests`），第二条生成安装包。安装包会在桌面和开始菜单创建“番茄桌面”快捷方式，图标取自 EXE 内嵌图标，卸载时一并删除。

默认输出为 `native/artifacts/DesktopNook-Setup.exe`。安装器为当前用户安装、无需管理员权限，默认装到 `%LOCALAPPDATA%\DesktopNook`，**向导第二页可自选程序安装位置**，`DirVerify leave` 会拦住当前用户不可写的目录；覆盖升级通过 `InstallDirRegKey` 沿用上次登记的位置。收纳数据目录固定为 `%LOCALAPPDATA%\DesktopNook`（不随程序位置改变），换目录安装时只清理旧位置的 `DesktopNook.exe` 与卸载器，目录非空时自动跳过，用户数据一律保留。静默安装仍可用 `/D=完整路径` 指定隔离目录。载荷用 `SetCompressor /FINAL zlib` 快速解压，升级时直接用旧 EXE 执行 `--maintenance=stop`，不再把 175 MB 载荷解压到 `$PLUGINSDIR` 第二次。可用 `/DOUTPUT=完整路径` 自定义产物位置，用 `/DPAYLOAD=完整路径` 指定单文件 EXE；编译期 `/DTESTROOT=隔离目录` 会把卸载登记键、历史安装位置与 `--sandbox` 全部隔离，用于端到端安装验证，绝不触碰真实安装。

安装器源码是 UTF-16 LE（含 BOM），`.gitattributes` 将其作为二进制保存以免被 Git 换行转换损坏。修改时应保留编码并统一 CRLF 行尾，**不要添加 `-*- coding: ... -*-` 编码声明**：NSIS 3.13 会按声明的编码读取脚本，与实际 UTF-16 不符时报 `Bad text encoding`（旧版 3.04 会忽略该声明，因此容易漏检）。

安装耗时与超时：载荷是约 142 MB 的 .NET 自包含单文件，全新安装只解压一次并跳过 `--maintenance=stop`（没有运行中的安装版）；覆盖升级才额外解压一份到临时插件目录执行 stop，通知旧实例退出后再替换 EXE，因此升级比全新安装慢。安装末尾的 `--maintenance=shortcut` 负责建立资源管理器入口，其中「固定到快速访问」依赖 Shell COM，资源管理器繁忙时可能长时间无响应：`Maintenance.Run` 把注册放进独立 STA 工作线程并限时 8 秒，超时写 `nav-pin-report.json` 的 `status="timeout"` 后正常返回；`App.xaml.cs` 还给所有维护命令加了进程级硬超时（shortcut 15 秒、其它 30 秒），保证 NSIS 的 `ExecWait` 不会无限等待。超时只影响「快速访问固定」这个尽力而为的入口，导航窗格注册表项与快捷方式不受影响，可用 `--maintenance=nav-pin` 事后重试。

## 发行新版本

从版本号同步、打包、验证到发布 Release 的完整可执行清单（含无 GitHub CLI 时的 REST API 路径、客户端校验规则与故障排查）见 [打包与发布](打包与发布.md)。以下为概要：

1. 更新 `native/DesktopNook.App/DesktopNook.App.csproj` 的版本，并同步 `native/scripts/Installer.nsi` 中的版本资源和安装登记版本。
2. 在 `native/releases/` 编写版本说明。
3. 构建并完成所需验证；将源代码提交到仓库。
4. 构建安装包，使用本机登录的 GitHub CLI 发布：

```powershell
pwsh -NoProfile -File native/scripts/Publish-Release.ps1 `
  -Executable native/artifacts/win-x64/DesktopNook.exe `
  -Installer native/artifacts/DesktopNook-Setup.exe `
  -NotesFile native/releases/v新版本.md
```

脚本只发布 `DesktopNook-Setup.exe` 与 `SHA256SUMS.txt`：先上传草稿并校验 GitHub 返回的哈希，再公开为最新版本。草稿上传失败可重跑续传；已公开的同版本文件不覆盖。加 `-VerifyOnly` 可核验既有产物。

发布脚本只处理发行文件，不会自动提交源码；源码需通过 Git 单独提交。后续版本应基于已提交的源码创建发行标签。改变发布仓库时，需要同时调整发布参数和 `OnlineUpdater.Repository` 中的客户端来源限制。

## 仓库边界

仅源码、必要图标和文档进入 Git。`bin/`、`obj/`、`artifacts/`、`test-results/`、本机收纳记录与恢复备份被忽略。发行 EXE 放在 Releases，不放进 Git 历史。
